# Nexor Design System

Este Storybook e a documentacao viva da lib compartilhada.

## Como usar

- componentes vivem em `project/packages/design-system/src`
- apps consomem via `@nexor/design-system`
- a marca ativa deve ser inicializada uma vez via `initDesignSystem({ brand })`
- componentes leem a marca pelo contexto e nao recebem `brand` como prop

## Objetivo

- documentar o comportamento real dos componentes
- reduzir variacoes visuais fora da lib
- acelerar a reutilizacao entre Nexor e Biteplaner
- preparar a futura evolucao para uma biblioteca multimarca mais robusta

## Regras atuais

- `Button`: apenas `primary`, `secondary` e `ghost`
- `Field`: um unico componente para `input`, `select` e `textarea`
- `Surface`: base unica para cards e paineis
- `Badge`: base unica para chips e rotulos pequenos

## Toolbar de marca

Use o seletor `Brand` na toolbar do Storybook para alternar entre:

- `Biteplaner`
- `Nexor`

Isso permite validar o mesmo componente com tokens e atmosfera diferentes sem duplicar stories.
